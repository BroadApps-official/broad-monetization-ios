# RU Billing при недоступном Adapty

Контракт BroadMonetization 1.5.4 (новый API с 1.5.0), 9 сентября 2026 года.

Приложение может продолжить загружать RU-тарифы со своего backend, когда
Adapty или продукты App Store недоступны, в том числе после удаления приложения
из магазина. Для этого разработчик явно подключает резервный загрузчик.
Обновление пакета само по себе не включает серверный резерв. Сигнатуры
существующих вызовов сохраняются. В 1.5.2 также исправлена подмена отдельных
каталогов `tokens` и `special_offer` основным paywall при ошибке загрузки.

## Условия

**Если Adapty не вернул ни одного продукта, в том числе успешно вернул `[]`,
достаточно RU/RUS-региона телефона или Storefront, чтобы подключённый резерв
сразу запросил свежие продукты с backend. Оба российских региона не требуются.**
Пустой успешный ответ обрабатывается с версии 1.5.3. Полученный `ru_pay=false`,
отсутствующий или некорректный флаг по-прежнему закрывает резерв.

| Текущий результат | Российский Storefront или регион iPhone | Действие |
|---|---|---|
| Продукты получены и есть точные совпадения с backend | Да, открытый RU gate | Прежний paywall и исходные SDK handles; RU checkout по точным совпадениям |
| Продукты получены, но ни один ID не совпал с backend | Да, свежий разрешающий RU gate | Все обычные серверные подписки с `isDefault=true` |
| Adapty не вернул конфигурацию | Да | Загрузить свежий каталог backend |
| Конфигурация содержит `ru_pay=true`, но продукты не загрузились | Да | Загрузить свежий каталог backend |
| Конфигурация содержит `ru_pay=true`, запрос продуктов успешен, но массив `[]` | Да | Сразу загрузить свежий каталог backend в той же попытке, без повторного нажатия |
| Получен `ru_pay=false`, отсутствующий или некорректный флаг | Любой | Резервная RU-ветка закрыта |
| Нет ни одного российского регионального сигнала | Нет | Резервная RU-ветка закрыта |
| Дополнительный placement обычной подписки не настроен | Любой | Сначала обычный fallback на main; если main недоступен, проверить RU-резерв |
| Сам main не настроен | Любой | Ошибка настройки, без резервного запроса |
| Свежий каталог недоступен или нет пригодных тарифов | Да | Сохранить обычный результат загрузки/ошибку и возможность повторить |

`RU` и `RUS` принимаются для Storefront и региона устройства. Русский язык,
IP, клавиатура и часовой пояс не являются регионом. Недоступный Storefront
не мешает, если регион iPhone российский.

Нет ответа и ответ без поля — разные случаи. Adapty-адаптер разбирает конфигурацию
**до** загрузки StoreKit-продуктов: ошибка продуктов не стирает полученный запрет.
Запрет любого проверенного placement сохраняется внутри одной попытки загрузки.
Одновременные попытки не делят это состояние.

`tokens` и `special_offer` используют собственные продукты: ни переход на `main`,
ни этот резервный каталог обычных RU-подписок к ним не применяются.

## Подключение

В готовой Adapty-композиции вызовите `makeServicesWithRUFallback` вместо
`makeServices`, передав дополнительный `ruBillingFallback: ruFactory`.
`ruFactory` — уже настроенный `RUBillingCompositionFactory` этого приложения:
тот же backend-контракт, пользователь, авторизация, регион и общий operation gate.
Остальные аргументы и UIFlows остаются прежними.

Если приложение собирает сервисы вручную:

```swift
let loadPaywall = ruFactory.makePaywallLoader(
    provider: adaptyPaywallRepository,
    cache: paywallCache,
    presentationLifecycle: adaptyLifecycle,
    staleLoadError: errors.stalePaywallLoad
)
```

Передайте этот loader в `BroadMonetizationServices.loadPaywall`. Сервисы RU checkout
подключаются как раньше через `ruFactory.makeServices`. Создание loader не включает
RU Billing в приложении без конфигурации backend и не добавляет API-ключи.
Существующие сигнатуры фабрик, `PaywallRepositoryProtocol` и `LoadPaywallUseCase`
сохранены; пользовательский провайдер может реализовать новый
`RUFallbackPaywallRepositoryProtocol`, возвращая доказательства текущей попытки.

## Данные и оплата

- Каталог приходит через `loadFreshCatalog()`: ошибка сети не заменяется кешем.
- С 1.5.4 резерв использует `RUExperimentCatalogSelector`: при отсутствии
  точных ID, пустом массиве или недоступном Adapty выбираются **все**
  `isDefault=true` из обычных подписок. Если defaults нет, сохраняется полный
  раздел подписок для совместимости со старыми каталогами.
- При наличии хотя бы одного точного совпадения по `catalogProductID` или
  `appStoreProductID` сохраняется исходный paywall провайдера. Defaults не
  добавляются к частичным совпадениям и не подменяют отдельную Apple-карточку.
  Для работающего Adapty сравнение требует обычного свежего разрешающего RU gate.
- Полный backend payload не меняется; выбранные строки сохраняют порядок,
  дубли и индексы в исходном каталоге. `isDefault` означает резервный набор,
  а не выбранную радиокнопку. `isSpecialOffer` остаётся отдельным экраном,
  токены — отдельным fulfillment. Неизвестные периоды выбранных подписок
  отображаются без возможности generic purchase.
- Источник продуктов — `.ruBackend`; ID, цена, валюта и период берутся из backend.
  Apple checkout для этих строк недоступен. Контракт `kind=subscription` требует
  согласия на рекуррентные списания; одноразовые товары требуют отдельной модели.
- Перед выбором метода и перед созданием платежа серверный каталог загружается
  заново. Выбранная строка проверяется по индексу, ID и полному отпечатку условий.
  Перестановка или изменение строки требует обновить paywall и выбрать заново.
- Разрешение резервной ветки живёт только в текущей презентации. Оно не записывается
  в JSON и не восстанавливается из кеша, не устанавливает `ru_pay=true` и не выдаёт
  кеш Adapty за `verifiedFreshRemote`.
- Эта ветка не создаёт Special Offer и не выдумывает A/B assignment. Без актуального
  эксперимента не отправляются отчёты о показе вымышленного варианта.
- Backend проверяет пользователя и создание платежа. Pending сохраняется до открытия
  браузера; возврат из браузера не подтверждает оплату. Premium открывает только
  Entitlement Engine после серверного подтверждения.

## Проверка обновления

`bash Scripts/module_gate.sh` включает `check_ru_provider_fallback_contracts.sh`:
матрицу ответов/регионов, запрет после сбоя продуктов, дубли с разными ценами,
проверку свежего каталога, отсутствие Apple checkout, сериализацию, отмену и
одновременные запросы. Дополнительно проверяются все defaults при сбое, `[]`
и непустом ответе без совпадений, приоритет точных/частичных ID, старый каталог
без defaults и исходные индексы после выбора подмассива.
Sandbox компилирует новый способ подключения и старые
сигнатуры. Настоящие purchase, restore и RU-платежи не выполняются.
